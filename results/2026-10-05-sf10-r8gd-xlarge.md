Things that bit me:
- Without `region` in the foreign table options, Aurora calls the global S3 endpoint to find the bucket
  region. From a private subnet with only the regional S3 gateway endpoint that times out after 2 s.
- A folder with hive partitions (`ship_year=1995/…`) is not read recursively: point `location` at a glob
  like `…/lineitem/*/*.parquet`. Partition columns are picked up and pruned (`Scanning Files: 1/7`).
- Adding a PostgreSQL function (`current_setting()`) to the select list broke the pushdown and the same Q1
  went past the 45 s Data API limit.
- Default `query_mem` on this instance is ~4 GB and the engine ran single-threaded. At 12 GB it used all 4 vCPUs.
